# 2026 축제 쿠폰 상가 신청 관리 확장 — 구현 계약

## 범위
- 기존 `/festival/2026/` 신청·접수 데이터 및 공개 페이지를 보존한다.
- 기존 관리자 인증·권한 검증을 재사용하며, 신청 페이지에 '관리자 로그인 / 신청자 관리' 링크를 추가한다. 링크만으로 권한이 생기지 않으며 API는 매 요청마다 서버에서 권한을 확인한다.
- 모바일 신청자 관리 화면의 겹침·가로 넘침·ISO 타임스탬프 원문 노출을 수정한다.

## 일괄접수
- 관리자 전용 CSV/XLSX 파일 선택 → 헤더 매핑 → 미리보기 → 검증 → 명시적 최종 접수.
- 필수 상호명·연락처 등 기존 폼 스키마를 그대로 따르며 파일 크기·행 수·형식을 제한한다.
- 전화번호 정규화와 기존 신청 ID/상호명/연락처를 조합한 중복 후보를 표시한다. 중복은 무조건 덮어쓰지 않는다.
- 모든 행의 성공/실패/건너뜀 결과를 내려받을 수 있게 한다. 재시도 시 idempotency key로 중복 생성하지 않는다.
- 파일 내용은 로그에 남기지 않는다. 원본 파일을 영구 보관하지 않는다.

## 선택 항목별 외부 공유
- 관리자에게 필드 선택 UI 제공: 상호명, 승인 여부, 정회원 여부, 신청일 등.
- 연락처·주소·대표자명 등 개인정보는 기본 선택 해제 및 권한/제공 근거 확인.
- 서버가 생성한 불투명 랜덤 토큰의 해시만 보관; 만료 시간, 폐기, 다운로드 허용 여부, 조회 로그 적용.
- 공유 페이지는 토큰에 허용된 필드와 승인된 행만 반환하고, 원본 관리 API를 호출할 수 없다.
- 공유 URL은 검색엔진 색인 차단, no-store, referrer 제한; 공유 취소 시 즉시 무효화.
- 공개 공유는 원칙적으로 승인된 상호명만, 민감 필드 포함 시 별도 인증과 최소권한 적용.

## 관리자 연결
- 신청 페이지의 관리자 링크는 기존 운영 인증 경로로 이동하고, 로그인 후 축제 신청관리 화면으로 돌아온다.
- 기존 관리자 계정 정책을 따르며 신규 이메일 자동 관리자 등록은 금지한다.
- 서버에서 역할·조직·행사 범위 검증, 변경 이력 기록.

## 테스트 및 운영 검증
1. 기존 7건 등 실제 운영 데이터가 삭제·중복·노출되지 않는지 백업 및 확인.
2. 비로그인·일반 사용자 API 접근 401/403, 관리자 접근 정상.
3. CSV/XLSX 정상·빈 파일·잘못된 헤더·수식 삽입·중복·대용량·부분 실패 테스트.
4. 공유 토큰 만료·폐기·필드 제한·권한 우회 테스트.
5. 360px 모바일에서 헤더·버튼·표 겹침 없음; 연락처는 관리자에게만 노출.
6. 스테이징 검증 → PR/CI → 배포 → 실서비스 URL에서 실제 확인.

## 운영 주의
실제 서비스 라우트 소유자, D1/DB 스키마, 관리자 로그인 리다이렉트, 공유 정책은 기존 코드 확인 후 확정한다. 이 문서만으로 기능 구현이나 배포를 주장하지 않는다.
